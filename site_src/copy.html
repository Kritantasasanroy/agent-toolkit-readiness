      The agent

      I wrote one brief that fixes every field and its allowed values (agent/prompts/research.md). Parallel research agents with web search and page fetch worked through the list, ten to fifteen apps each. Each agent writes one JSON profile per app, and every claim about auth, access, API style and MCP has to carry a quote from a vendor page.

      Where Composio fits. The research itself ran on my own agents, and I did not drive it through the Composio SDK. I did use my Composio API key in three places, each as a check on the agents' work. The toolkits API shows which apps already have a toolkit. Its auth methods gave me a second opinion on my own answers, which is how the Twilio and Sentry misses turned up. And a tool-router session gave me a remote shell, where I re-ran the evidence check from a different network.

      1. ResearchAgents read vendor docs and write a profile per app with quoted evidence.
      2. ValidateA script rejects any profile with a value outside the brief, or a cited field with no evidence.
      3. Check the linksA script fetches every cited page and looks for the quote word for word.
      4. ReviewA second agent gets each profile plus the link results and has to prove or fix every field from the raw page text.
      5. ScoreAnswers are compared with a hand-checked sample. Every answer the two passes disagreed on goes to a fresh agent that sees only the two options.
      Judgement call6. Contested answersWhere that check did not back the second pass, the vendor docs were read again and each answer was settled with a source and a note.

      Where it needed help. Pages built with JavaScript (Intuit, Xero, Coda, Ramp and others) returned nothing to a plain fetch, so the agents fell back to GitHub READMEs, llms.txt files or help articles. Several vendor sites refuse automated requests. of the citations in the final data could not be checked because the page refused the request, errored or was too large. Those quotes are unconfirmed, and I have not counted them as confirmed.

      Where a person was needed. I wrote the brief and the allowed values, drew the reference sample, and wrote its answers from vendor docs with AI assistance. After a live request I corrected two of those answers myself (Podio and Gorgias both publish official MCP servers, and my first reference said they did not). Copper stays open. Its own pages do not say whether the API works during the trial, and I did not want to guess.

      Evidence, the mechanical check

      What defeated the agent

      A few apps have thin or contradictory public information. I have said so here and not guessed. fanbasis now redirects to commas.com and publishes no developer docs, so its auth value is a placeholder. Paygent Connect has no product site of its own, so its profile describes NMI, the gateway the brief names. iPayX's vendor files disagree on free-tier limits. Salesforce Commerce Cloud's developer pages refused every fetch. Gumroad's help article is built in the browser, so none of its four quotes could be confirmed from the page text. apps are marked low confidence for reasons like these, and every profile's notes field lists its own assumptions.
