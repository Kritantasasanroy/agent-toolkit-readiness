      The agent

      I cross-checked the list against Composio's toolkits API, using a Composio API key. I wrote one brief that fixes every field and its allowed values (agent/prompts/research.md) and ran it as parallel Claude Sonnet 5.5 sub-agents with web search and page fetch, ten to fifteen apps each, from a Claude Code session. Each agent writes one JSON profile per app, and every claim about auth, access, API style and MCP has to cite a quote from a vendor page.

      1. ResearchAgents read vendor docs and write a profile per app with quoted evidence.
      2. ValidateA script rejects any profile with a value outside the brief or a cited field with no evidence.
      3. Check the linksA script fetches every cited page and looks for the quote word for word.
      4. ReviewA second agent gets the profile plus the link results and has to prove or fix each field from raw page text.
      5. ScoreAnswers are compared with a reference sample, and every answer the passes disagreed on goes to a blind adjudicator.
      Needed a human6. Contested answersWhere the checks disagree with each other, a person decides.

      Where it needed help. Pages built with JavaScript (Intuit, Xero, Coda, Ramp and others) returned nothing to a plain fetch, so the agents fell back to GitHub READMEs, llms.txt files or help articles. Several vendor sites refuse automated requests. of the citations in the final data could not be checked, because the page refused the request, errored or was too large, so those quotes are unconfirmed rather than confirmed.

      How I know how accurate it is

      Evidence, the mechanical check

      The pass 1 agents reported that their fetch tool returns summaries of pages, so many "quotes" were paraphrases. Of the citations whose page loaded, % held the quoted text in pass 1 ( of ). After the review agent re-copied quotes from raw page text it is % ( of ). The match ignores case, spacing and typographic quote marks. This is the clearest gain, and a script measured it.

      I then ran the same check a second time inside a Composio sandbox (a tool-router session with a remote shell, driven with the Composio API key), so the pages are fetched from a different network. Of citations, my machine found the quote on and the sandbox on . The sandbox found that my machine could not reach, and my machine found that the sandbox did not. I have not looked into why the two differ; blocked requests and slow pages are the likely causes.

      Answers, the reference sample

      I drew apps, two per category, with a fixed seed, and wrote reference answers from vendor docs for six fields each. Pass 1 scores on it and pass 2 scores , so the sample does not separate them. It is also not independent: I wrote the reference with Claude's help, and of its single-value answers accept more than one reading, in of the apps. I also had to correct two entries (Podio and Gorgias both publish official MCP servers; my first reference said otherwise). Treat it as a sanity check, not proof. For the two list fields (auth methods and API styles) a correct first answer plus any subset of the accepted values counts as right, so omissions are never penalised and those scores measure precision, not completeness.

      Answers, the disputes

      The more useful test is the answers the passes disagreed on. Pass 2 changed fields across apps. I added the sample misses, giving disputed answers, and gave each to a fresh agent that saw only the two competing values (shuffled, unlabelled) and had to settle it from vendor docs.

      Of the changes, the docs supported pass 2 times and pass 1 times, could not be settled, and for the docs support both readings. So the second pass fixed more than it broke, but it also introduced errors, and I would not call it uniformly better. The adjudicator is not infallible either: it ruled against official MCP servers for Podio that a live request and the vendor's own guide show exist.       What defeated the agent

      A few apps have thin or contradictory public information, and the page says so instead of guessing. fanbasis now redirects to commas.com and publishes no developer docs, so its auth value is a placeholder. Paygent Connect has no product site of its own, so its profile describes NMI, the gateway the brief names. iPayX's vendor files disagree on free-tier limits. Salesforce Commerce Cloud's developer pages refused every fetch. apps are marked low confidence for reasons like these, and every profile's notes field lists its own assumptions.
